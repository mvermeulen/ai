Distributed System Guide

1. Launch Worker Daemons

To easily deploy the C++ daemon to Ubuntu/Debian machines, build and install the Debian package:

./distributed/package_deb.sh
# Copy the .deb to worker machines
sudo dpkg -i hailstoned__amd64.deb

This installs the hailstoned daemon as an xinetd service running automatically on port 5429. The daemon automatically runs startup micro-benchmarks on available backends (CPU, Vulkan, HIP) to register throughput.

Alternatively, you can compile and start it standalone:

./build/hailstoned --port 5429

2. Register Workers

Add workers by submitting their IP:Port in the "Add Worker Daemon" section, or define them on startup of the controller:

python3 distributed/controller.py --workers IP:5000 --port 8080

3. Dynamic Partitioning & Timeouts

The scheduler divides ranges into chunks sized to take approximately your configured Target Job Duration (e.g. 1 minute) based on the worker node's speed. Powerful GPUs process larger chunks than slower CPUs.

4. Fault Tolerance

If a worker node crashes, goes offline, or takes longer than its expected run duration (plus buffer), the controller cancels the task and re-queues the search range, protecting against data loss.

5. Flexible Search Mode

The Start Number and End Number fields support mathematical expressions (e.g. 2^32) and scientific notation (e.g. 1e12).

Continuous & Resume Mode: You can leave the Start Number blank to automatically resume from the loaded checkpoint's current position. Leave the End Number blank to run an infinite, continuous search across the cluster.
